Why LessDB

Agents and humans, same data, same database.

01

“What do my agents see that my team doesn't?”

Nothing, and that's the point. Two front doors on one engine: agents get tool-shaped access — query, schema, stats, search, link — while people get SQL, the REPL, and SDKs. Shared SQL tables stay in one engine; context, memory and vector namespaces can be scoped per agent. No export step is required for the local path.

02

“Why run one system for agents and another for people?”

Split systems drift and double your ops. LessDB keeps SQL, vector search, and linked knowledge in one engine, so agent work and human work use the same engine and governed data paths.

03

“What happens when the work outgrows one machine?”

Point tables at shared object storage and compute nodes become stateless — durable data lives in the shared store. Scale the swarm, not the toil.

Features

Everything both sides need, embedded.

✦

MCP server, 28 tools

One stdio connection: query, schema, stats, tables, search, and links — for Claude Code, Codex, Cursor, and any MCP client.

≋

Full SQL

Joins, CTEs, window functions, and subqueries with a cost-based optimizer. The REPL, the SDKs, and agents all run the same engine.

❖

Knowledge graph

Titled, tagged notes with typed links, BFS, shortest paths, and ranked search — plus RAM tables with point lookups.

◉

Vector search built in

Named vector spaces with l2/cosine/dot metrics. Exact flat search plus IVF-PQ ANN with exact re-ranking — 0.87 recall@10 at 8.7k QPS.

▤

Columnar storage

Immutable data parts with per-column zstd/lz4 compression. Typed min/max stats and bloom filters prune parts before any I/O.

⇄

Shared object storage

Tables on S3, GCS, or Azure Blob: any node with the same URL sees the data instantly — compute is cattle.

⚡

GPU kernels (optional)

Optional wgpu kernels cover filtered sums and dot products on Metal/Vulkan; CPU fallback remains available and automatic threshold dispatch is roadmap work.

⌁

Observable by default

Prometheus metrics with pruning effectiveness, query histograms, auth failures, and memory — exposed at GET /metrics.

⛨

LDAP / AD auth

Fail-closed group→role mapping over LDAPS, injection-safe user filters, and role-based authorization on every HTTP endpoint.

Control & governance

Explicit boundaries for agents and humans.

Hosted HTTP requires agent tokens and applies role checks; local stdio authentication is optional for development. MCP calls write audit entries. Context, memory and vector tenant namespaces are scoped, but that is not universal row-level isolation for shared SQL tables.

  • i Hosted HTTP agent tokens with admin / read / write role checks
  • i Tenant namespaces for context, memory and vector state
  • i MCP audit entries include caller, tool, SQL and outcome
  • i Table grants, row-level ACLs and approval gates remain application/roadmap work

Quickstart

A short path to a shared database

The complete guide, start to finish. Install, ingest, query — then open the same data to your agents over MCP and your team over SQL and the SDKs.

1

Install with curl

One line installs the prebuilt lessdb binary (macOS arm64, Linux x64).

$ curl -fsSL https://lessdb.dev/install.sh | sh

# The installer fetches the release for your OS/arch from the
# Cloudflare package host and puts `lessdb` on your PATH.
$ lessdb --version                            # lessdb 0.6.0

# Prefer building from source? (Rust ≥ 1.89)
$ cargo install --path crates/less-cli --features cloud,gpu

The installer writes the binary to ~/.local/bin and may add PATH lines to your shell rc files. To uninstall, remove the binary and those lines; do not delete your database directory.

2

Your first database

$ lessdb init        # creates .less/ here — or --dir /data/mydb
3

Tables + data

$ lessdb create "CREATE TABLE events (
    id Int64, kind String, amount Float64, ts DateTime
) ENGINE = Firefly ORDER BY (kind, id) UNIQUE (kind) COMPRESSION = 'zstd'"

# CSV headers map to columns (any order); empty/`\N` cells are NULL:
$ lessdb insert events --csv events.csv          # or --jsonl / --parquet / --arrow
$ lessdb sql "INSERT INTO events VALUES (2, 'view', 1.5, '2025-01-01 10:01:00')"
$ lessdb sql "COPY (SELECT * FROM events) TO 'export.parquet'"
4

Query (SQL-first)

$ lessdb sql "SELECT kind, count(*) AS c, sum(amount) AS total
          FROM events GROUP BY kind ORDER BY total DESC"

$ lessdb sql "SELECT * FROM events WHERE kind = 'click' AND ts > '2025-01-01'"

$ lessdb sql                                      # interactive REPL (end with ;)
$ lessdb sql "EXPLAIN SELECT ..."                 # plan + part-pruning info

Full SQL surface: joins, CTEs, window functions, subqueries. UNIQUE columns dedup keep-last at flush/merge; run lessdb optimize events to enforce across parts. lessdb describe events / lessdb parts events show storage state.

5

Vector search

$ lessdb vector create docs 3 --metric cosine                    # flat exact
$ lessdb vector create big 256 --index ivf_pq --nlist 64 --m 8   # ANN
$ lessdb vector add docs --vectors '[[1,0,0],[0,1,0],[0.9,0.1,0]]' \
                    --payloads '[{"title":"rust"},{"title":"python"},{"title":"rust-like"}]'
$ lessdb vector search docs '[1,0,0]' --k 2
$ lessdb vector embed "rust database"        # built-in trigram embedder (demo)

# SQL, too — and you can join/filter the hits:
$ lessdb sql "SELECT id, payload FROM vector_search('docs', [1.0,0.0,0.0], 10)
          WHERE payload LIKE '%rust%'"
6

Knowledge graph: contexts + links

Link notes, tasks, and projects in the same data dir — no extra services.

$ lessdb context put proj/lessdb "LessDB" "Analytical DB in Rust" --tag db --kind project
$ lessdb context put task/123 "GPU kernels" "wgpu filtered-sum + dot" --tag gpu --kind task
$ lessdb context link task/123 proj/lessdb depends_on
$ lessdb context find gpu
$ lessdb context neighbors task/123 && lessdb context path task/123 proj/lessdb

$ lessdb memory create people --field id:Int64 --field name:Utf8 --pk id
$ lessdb memory insert people '[{"id":1,"name":"ada"},{"id":2,"name":"grace"}]'
$ lessdb memory sql "SELECT count(*) FROM people"

Everything persists under .less/memory/.

7

Open the agent door (MCP)

One stdio connection exposes 28 tools to any MCP client — no plugins, no sync jobs.

$ lessdb mcp            # stdio JSON-RPC, uses --dir .less by default

# Lock the door and hold agents accountable:
$ lessdb token create claude --role read --tenant default   # prints the token once
$ lessdb mcp --require-auth      # tokens required, roles enforced, fail-closed
$ lessdb audit --since 24h       # recent recorded MCP calls

Claude Code:

$ claude mcp add lessdb -- lessdb mcp --dir /abs/path/to/mydb

Claude Desktop claude_desktop_config.json:

{ "mcpServers": { "lessdb": { "command": "lessdb", "args": ["mcp", "--dir", "/abs/path/to/mydb"] } } }

Agents get 28 tools: lessdb_query/explain/schema/stats/tables/optimize, context_*, memory_*, vector_*.

8

HTTP server (+ Prometheus, LDAP)

$ lessdb server --addr 127.0.0.1:7080
$ curl -s localhost:7080/health
$ curl -s localhost:7080/v1/sql -H 'content-type: application/json' \
     -d '{"sql":"SELECT count(*) FROM events"}'          # JSON
$ curl -s localhost:7080/metrics                           # Prometheus text

# LDAP/AD auth (fail-closed group→role mapping):
$ lessdb init --auth @auth.json   # see docs/ARCHITECTURE.md §9 for the schema
$ curl -u demo-user:REDACTED_PASSWORD -H 'content-type: application/json' \
     -d '{"sql":"SELECT 1"}' localhost:7080/v1/sql

Prometheus:

scrape_configs:
  - job_name: lessdb
    static_configs: [{ targets: ["localhost:7080"] }]
9

Cloud-native: compute/storage separation

$ lessdb init --shared s3://my-bucket/lessdb        # parts + catalog in S3

Any node with the same --shared URL can discover the same tables; local disk stays ephemeral (buffers/caches only). file:// for local dev.

10

Python / Node (embedded)

# npm — the CLI as a package (postinstall fetches + verifies the binary):
$ npm install -g lessdb --registry https://lessdb.dev/npm/
$ lessdb sql "SELECT 40 + 2"
$ npx --registry https://lessdb.dev/npm/ lessdb --version        # one-shot, nothing installed

# Homebrew — no neutral public tap is advertised yet; see Downloads.
⚡

Benchmarks & GPU

$ lessdb bench --rows 5000000     # insert + scan/filter/group-by throughput
$ lessdb gpu                      # GPU vs CPU kernels (Metal/Vulkan)
$ lessdb metrics                  # this process's Prometheus metrics
